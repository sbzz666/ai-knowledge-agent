# 架构决策记录

## 产品定位

构建一个可部署、可评测、回答可溯源的知识库 RAG Agent。首个演示场景建议使用虚构的企业制度、产品手册或课程资料，避免把真实个人信息提交到公开仓库。

## 核心链路

```text
上传 → 文件校验 → 解析 → 结构化切分 → Embedding → 索引
提问 → 查询改写 → 混合召回 → RRF 融合 → 重排 → 生成 → 引用校验
```

## 关键设计选择

### PostgreSQL + pgvector

同一数据库保存用户、知识库、文档元数据、全文索引与向量，降低早期部署复杂度。后续数据量显著增长时，再评估独立向量数据库。

### 混合检索

向量检索适合语义相似内容，关键词检索对编号、产品名、专有名词更稳定。两路召回用 Reciprocal Rank Fusion 合并，再按需使用重排器。

### 引用优先

回答结构必须包含 source、page、chunk_id 与 quote。生成结束后检查引用是否真实存在于检索上下文；证据不足时返回“不确定”。

### 框架适度使用

基础文档解析和检索逻辑保持为普通 Python 模块。只有出现查询改写、工具选择、重试、人工确认等有状态流程时才引入 LangGraph，避免项目被框架绑死。

## 评测计划

- 检索：Recall@5、Recall@10、MRR。
- 生成：答案正确性、忠实度、引用命中率、拒答准确率。
- 工程：P50/P95 延迟、单次调用成本、解析失败率。
- 回归：固定一组问题与证据，每次修改自动运行。

## 部署路径

1. 本地：Docker Compose 启动 API 与 pgvector。
2. 演示：Streamlit Community Cloud + 托管 PostgreSQL，或单容器平台。
3. 正式作品：Web、API、数据库拆分；GitHub Actions 自动测试并构建镜像。
